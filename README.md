# Polymarket BTC 5-minute price-entry strategy

The demo bot polls a public CCXT BTC spot ticker every **500 ms** and compares the latest price with a sample about **1,000 ms earlier**. It continues to calculate the **99th percentile of absolute one-second BTC moves** over a rolling window of up to **5 minutes**, with a **$1 minimum threshold**, for dashboard monitoring only. BTC signals are not required to enter and do not choose the trade side. The dashboard reports threshold warm-up and feed health.

After a five-minute market window opens, the bot waits **180 seconds**. Then the first UP or DOWN token whose best ask is between **$0.20 and $0.45**, inclusive, can trigger the window's single entry. Order size starts at **500 shares**; each loss adds **200 shares** to the next entry, and one win resets it to 500. BUY orders can sweep asks up to **50% above the observed best ask** by default (configurable with MAX_BUY_SLIPPAGE_PERCENT), but execution is capped at **$0.45**. The simulator records the full target share count at a valid trigger; any quantity beyond visible ask depth is modeled at the order price limit. After entry, the position is held for settlement; no second entry is allowed in that window.

Coinbase BTC/USD is the default informational feed. Set CCXT_EXCHANGE and, if needed, CCXT_SYMBOL to select another CCXT market; the feed honors an exchange's higher minimum interval if it requires one. Binance returned a location restriction from this runtime, so Binance connectivity is not assumed. Feed staleness is reported but does not prevent price-only entries.

Demo marketable BUY orders sweep visible Polymarket asks after the chosen token's best ask enters the $0.20-$0.45 band. Execution is capped at $0.45 even when the configured slippage allowance would allow more; if visible depth runs short, the simulator fills the remaining target shares at the order's price limit. Thin books within that cap are topped up with modeled liquidity at the price limit so every target share is recorded as filled; this is synthetic demo liquidity, not actual market depth. Estimated crypto taker fees are included in demo cash and P&L. A held-side CLOB midpoint at or above **$0.99** is counted as a $1 payout per remaining share; a best bid at or below **$0.01** is counted as $0.00. This is a demo threshold heuristic, not official resolution. Other shares still open at the five-minute close wait for official Polymarket resolution. Account equity is cash plus the marked value of all open shares; total P&L is equity minus starting capital, and marks remain available when the active market rolls over.

This strategy is strictly demo-only. LIVE_TRADING=true is refused before wallet authentication, and the active bot uses only DemoTrader. The $10,000 paper balance, trade history, and loss-step sizing reset when the process restarts. Simulated fills, estimated fees, and P&L are behavior checks—not evidence of live execution or profitability.

Run npm test from this directory to verify the feed, adaptive threshold, price-entry behavior, share progression, and live guard. For local startup and dashboard checks, follow DEMO_RUNBOOK.md.
